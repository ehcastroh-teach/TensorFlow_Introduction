# An Introduction to TensorFlow V.2

TensorFlow (TF) is an open-source library for dataflow programming, differentiable computation, and machine learning. This repository introduces TF V.2 from the ground up - covering tensors, operations, automatic differentiation, and the `@tf.function` decorator - so that readers without a prior machine learning background can build confidence with the framework before applying it to real models. By the end you will understand not only how to write TF code, but why the library is designed the way it is.

---

## Learning Objectives

By working through this repository you will be able to:

- Create and manipulate `tf.constant` and `tf.Variable` tensors across scalar, vector, matrix, and higher-rank shapes
- Perform arithmetic, linear algebra, gradient, and slicing operations on tensors
- Understand eager execution and why it simplifies debugging compared to TF 1.x graph execution
- Use `tf.GradientTape` to compute partial derivatives and build a hand-written gradient-descent training loop
- Set up TensorBoard and interpret its training curves and computation-graph panels
- Decorate Python functions with `@tf.function` to compile them into portable TensorFlow graphs
- Recognize when to use `@tf.function` and when to stay in eager mode, including how tracing and polymorphism affect side effects
- Handle special tensor types: ragged, string, and sparse

## Step-by-Step Walkthrough

### Part 0 - About and Motivation

TF V.2 ships with eager execution on by default. Tensor operations run immediately and you can inspect values with a plain `print()` - no `Session.run()` required. The notebook opens by confirming this is active and explaining why it matters: interactive debugging becomes straightforward, and the gap between experimenting and understanding is far smaller than in TF 1.x. Understanding this default behavior prevents a large class of beginner confusion before it starts.

### Part 1.1 - TensorFlow Setup

The first thing the notebook does is install and version-check TF. Version mismatches between TF, Keras, and CUDA are one of the most common sources of cryptic errors in downstream cells. Establishing a known-good environment first means any errors that appear later are almost certainly in the user's code, not the environment.

### Part 1.2 - TensorBoard Setup

TensorBoard is TF's built-in visualization dashboard. The demo trains a small MNIST classifier - not to teach classification, but purely to generate event logs that illustrate what TensorBoard shows. The key practical points are: where logs are written (the `logs/` directory), how to load the Jupyter extension (`%load_ext tensorboard`), and how to point TensorBoard at a log directory. Learning this early means you can monitor any training run you write later without extra setup.

### Part 1.3 - TF Tensors

Tensors are the core data structure throughout TF. The notebook walks through:

- `tf.constant` - immutable tensors initialized from Python values or NumPy arrays; lowercase `c` signals it is an operation, not a class
- `tf.Variable` - mutable tensors representing model weights; uppercase `V` signals it is a class with its own methods (`assign`, `assign_add`, `assign_sub`)
- Scalar (rank-0), vector (rank-1), matrix (rank-2), and higher-rank shapes, shown with diagrams
- Building tensors from distributions (`tf.random.normal`, `tf.random.uniform`) and converting NumPy arrays
- Optional sections on variable lifecycles, naming, and device placement across CPU and GPU

The `tf.constant` versus `tf.Variable` distinction matters for training: only `tf.Variable` objects track gradients by default and can be updated in place.

### Part 1.4 - TF Operations

TF operations follow NumPy conventions closely, which lowers the barrier if you already know NumPy. The notebook covers:

- Arithmetic: `tf.add`, `tf.multiply`, `tf.matmul` and their operator-overloading equivalents (`+`, `*`, `@`)
- Gradients: `tf.GradientTape` records every differentiable operation performed inside its context so gradients can be computed afterward - this is the same mechanism that drives backpropagation in every TF model
- Indexing and slicing: integer indexing removes a dimension; range indexing preserves it - the same semantics as NumPy
- Reshape: any reshape is valid as long as the total element count stays the same
- Optional: broadcasting, ragged tensors, string tensors, sparse tensors

### Part 2.1 - `@tf.function`

Eager execution is ideal for debugging but carries Python interpreter overhead. `@tf.function` traces a Python function once - reading through it and recording the TF operations into a computation graph - and then runs that compiled graph on every subsequent call. The speedup can be significant for repeated operations like training steps.

The section covers four practical consequences of this design:

- Tracing happens once, so Python `print()` statements inside a decorated function only fire during the trace, not on every call - you must use `tf.print` if you want output on every execution
- Polymorphism: `@tf.function` builds a separate graph for each unique input dtype or shape it encounters, so one decorated function can handle `int32` and `float32` inputs transparently
- `get_concrete_function`: retrieves the specific compiled graph for a given input signature, useful for export or inspection
- Input signatures: supplying `input_signature=[tf.TensorSpec(...)]` locks the function to a single shape and dtype, preventing accidental graph proliferation when working with dynamic shapes

### Homework - Applying the Concepts

The homework notebook progressively tests the same ideas in more demanding contexts:

1. **Tensor ops and graph visualization** - create typed tensors, trigger a `@tf.function` trace, and read the resulting computation graph in TensorBoard's Graphs panel
2. **GradientTape from scratch** - compute partial derivatives of a two-variable polynomial analytically and verify them against `tf.GradientTape`
3. **Gradient descent on real data** - load the scikit-learn diabetes regression dataset, standardize features, initialize `tf.Variable` weights, and write a 200-step gradient-descent loop that minimizes mean squared error - the same pattern used inside every `model.fit()` call

## Key Concepts Glossary

| Term | Plain-language definition |
|---|---|
| Tensor | A multidimensional array - the basic unit of data in TensorFlow |
| Rank | The number of dimensions of a tensor (scalar = rank 0, vector = rank 1, matrix = rank 2) |
| Eager execution | Running TF operations immediately and returning concrete values, rather than building a graph first |
| `tf.constant` | An immutable tensor; its value cannot change after creation |
| `tf.Variable` | A mutable tensor; typically used for model weights that are updated during training |
| `tf.GradientTape` | A context manager that records differentiable operations so gradients can be computed afterward |
| Gradient | The rate of change of a function with respect to its inputs - the core signal for updating model weights during training |
| Automatic differentiation | Computing exact gradients by recording and replaying the chain rule through a sequence of operations, rather than approximating numerically |
| `@tf.function` | A decorator that compiles a Python function into a TensorFlow computation graph |
| Tracing | The one-time process by which `@tf.function` reads through a function and records the TF operations into a graph |
| Graph execution | Running a precompiled computation graph rather than interpreted Python - faster for production workloads |
| Polymorphism | The ability of `@tf.function` to maintain separate graphs for different input dtypes or shapes under a single Python function name |
| Broadcasting | Automatically expanding a smaller tensor to match the shape of a larger one during element-wise operations |
| TensorBoard | TensorFlow's built-in dashboard for visualizing training metrics, computation graphs, and profiling data |
| Ragged tensor | A tensor where rows can have different lengths, used for variable-length sequences |
